Live prototype

Homli: trusted PG discovery

The problem. Moving to a new city means piecing a PG together from word of mouth, Maps, listing portals and photos. The facts are scattered, often missing, and photos can mislead.

What it does. Search by area, by PG name, or in plain language ("AC under 20k in Bellandur"). Filters, a distance slider, shortlist, compare up to three, and a demo visit request with duplicate protection. Every page shows where its information came from.

Open the live site Code on GitHub Product docs

The first load can take up to a minute while the free server wakes up.

Decisions I made

  • Unknown is never guessed. If a source does not say, the page says "Details being verified".
  • No scraping and no invented reviews. Photos are used only with permission, and credited.
  • The Google API key stays on the server, never in the browser.
  • Booking is a clearly labelled demo. Nothing is sent to a PG and no money moves.

Built with

JavaScript, Node and Express, Postgres, GitHub Pages, Render and Neon. 29 automated tests.

Honest notes

A prototype with 11 PGs from firsthand information and public pages. Built with an AI assistant (Claude Code): I set the problem, rules and scope, tested it, and deployed it myself. The problem comes from one friend's experience and has not been validated with more users.

Aptitude game: practice that feels like a game

The problem. Aptitude preparation is repetitive and hard to stick to: open a question bank, solve MCQs, see a score, leave.

The idea. A mountain world with six aptitude trails, short levels, interactive question types instead of only MCQs, a Daily Challenge with a streak, and concept mastery computed from real answers.

Planned first version. Start as a guest, two fully built genres of 10 levels each, three interactive question types, stars, XP and coins, Daily Challenge, streak, and one Survival Room prototype, deployed with a public link.

Honest status: I am building it now. The problem is a hypothesis from my product brief, and I have not yet tested it with users.

How I work

Say what I do not know

I mark observations, hypotheses and illustrative numbers as what they are, in my decks and in my products.

Show the trade-off

Every choice names what it gives up. In the Instagram deck, the winner scored 327 against 298, and I said it needs validating.

Respect the source

Photos only with permission and credit. No scraping, and no reviews I cannot trace.

Build it, then explain it

I ship a working version, then work through how each part works, so I can defend it.
